# v0.1.0 — diagnostic scaffold

The first scaffold release keeps Codex as orchestrator and merge authority,
uses OpenCode only as a bounded local-worker runtime, and makes architectural
behavior inspectable through append-only records and a localhost dashboard.

## Included

- issue-bounded coder, reviewer, helper, and advisory routing;
- deterministic evidence, review, merge-gate, and merge-publisher boundaries;
- separate local and frontier token accounting;
- delivery health and generated-artifact detection;
- immutable worker health, lifecycle, and adjudication ledgers;
- derived claimed-versus-observed outcomes, contradictions, correction
  lineage, and Codex interventions;
- GET-only localhost diagnostic dashboard;
- sanitized four-state replay with two passes, one hidden failure after worker
  success, and one interrupted correction.

## Validation

- 179 repository tests passed.
- Candidate worker shell syntax and diff whitespace checks passed.
- Live timeout smoke produced start, timeout, and failed health facts.
- Dashboard replay showed four adjudicated runs, one contradiction, one
  interrupted correction, and zero frontier tokens.
- Dashboard source ledgers remained byte-for-byte unchanged after reads.
- Secret-pattern scan found no credential-like values in release fixtures.
- Shadow install backup: `20260815T175508Z-486553`; installed candidate hash
  matches the freeze record and the baseline worker hash remains unchanged.

## Known limitations

- Qwen3.8-27B is useful for bounded direct advisory work, but its OpenCode
  mapper/tool loop is not efficient enough for promotion.
- Qwen3-Coder-Next passed routine and moderate tasks but missed reader
  atomicity in the difficult concurrency task.
- The independent local reviewer timed out after 600 seconds, 61 turns, and
  2,220,419 local tokens on the diagnostic PR; Codex performed final review.
- Live ledgers created before lifecycle v1 cannot recover missing identity
  automatically; the release replay contains explicitly adjudicated facts.
- The frozen baseline-v2 versus candidate performance comparison remains a
  separate tracked experiment, not a release-score gate.
- The dashboard is local only and has no remote authentication threat model.

The next action is a human/Codex release review. No `0.1.x` experiment begins
automatically.
