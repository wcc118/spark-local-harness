# v0.1.0 diagnostic scaffold

`v0.1.0` is the first usable scaffold, not a claim of architectural maturity.
The project intentionally remains in the `0.x` series while evidence continues
to change its behavior.

## Release path

1. Record the release scope and pre-release checkpoint. **Complete.**
2. Capture append-only adjudications and complete run lifecycles. **In progress.**
3. Derive a diagnostic read model without rewriting source ledgers.
4. Provide a local read-only dashboard.
5. Replay routine success, moderate success, hidden failure, and interruption.
6. Validate tests, sanitization, immutability, and human readability.
7. Freeze configuration and tag `v0.1.0`.
8. Pause for human/Codex review before beginning `0.1.x` experiments.

The checkpoint before diagnostic completion is commit
`62ca81bac1b6674aca4781ed8477cdbcd9f63bb3`.

## Version scale

- `0.1.x`: narrow diagnostic, routing, threshold, prompt, or reliability changes.
- `0.x.0`: measured behavioral changes requiring matched smoke tests.
- Larger `0.y.0` increments: substantial architecture changes with a frozen
  predecessor and rollback plan.

`1.0.0` is not a target. The harness is a recursively observed learning system.

## Invariants

- Codex owns orchestration, escalation, final judgment, and merge authorization.
- Workers execute one bounded task and never become a second orchestrator.
- Raw health, lifecycle, and adjudication ledgers are append-only.
- Worker claims never substitute for independent observed outcomes.
- The dashboard is read-only and cannot launch workers, change configuration,
  modify telemetry or GitHub state, or merge work.
